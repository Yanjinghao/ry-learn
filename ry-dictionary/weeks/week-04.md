# 第 4 周：RBAC 权限 + 作品 1 交付

**目标：** 自己做一套最小 RBAC，前端按权限藏菜单和按钮；打磨为可演示的作品 1。  
**前置：** 登录、商品、订单已可跑。  
**产出：作品 1**  
**项目目录：** 继续 `D:\workspace\ry\week1_shop`

---

## 周末验收（作品 1）

- [ ] 至少 2 个角色：`admin` / `shop`
- [ ] `shop` 看不见「用户管理」菜单，直接打接口也 403
- [ ] `shop` 看不到别人的订单（数据权限）
- [ ] 登录后返回：用户信息 + 角色 + 权限字 + 菜单树
- [ ] 前端动态路由 + 按钮权限（`v-permission` 或等价实现）
- [ ] README 含架构、启动步骤、演示账号；能 3 分钟讲完

---

## 工作日建议（每天 3h）

### 周一

- 建 `role`、`menu`、`user_role`、`role_menu`
- 写死两套数据：admin 全权限；shop 仅商品与自己的订单
- menu 字段至少有：`path`、`component`、`perms`（如 `product:edit`）、`type`（目录 / 菜单 / 按钮）

### 周二

- 登录成功后组装：角色列表、权限字列表、菜单树
- 前端先用 mock 菜单跑通动态路由，再换成真实接口

### 周三

- 后端鉴权：自定义注解或拦截器校验权限字
- 无权限返回 403（与 401 区分：401 未登录，403 已登录无权限）
- 用 Apifox 分别带两个角色的 token 打同一接口

### 周四

- 数据权限：订单列表按 `user_id` 过滤；admin 不过滤
- AOP 记操作日志到 `oper_log`（谁、何时、哪个接口、是否成功）

### 周五

- 前端：动态路由 + 按钮隐藏
- 改角色权限后，重新登录生效（本周不必做即时踢人）
- 写 README；列演示话术（两个账号对比）

### 周六（3～4h）

- 全流程演示：登录管理员 → 管用户/商品 → 切 shop → 只能看自己的订单
- 打 tag：`work1-v1`
- 请自己按 README 从零启动一遍（或换目录重装依赖）

### 周日（2～3h）

- 定稿口述：角色、菜单、权限字、数据权限各管什么
- 预习第 5 周：若依目录、`TokenService`、登录链路

## 面试可讲点

- 401 vs 403  
- 菜单隐藏不等于接口安全（前端藏按钮，后端必须再校验）  
- 数据权限和功能权限的差别  
- 这套模型和若依 `sys_user / sys_role / sys_menu` 的对应关系（下周对照）

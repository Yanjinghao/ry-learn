## 周末验收（作品 2）

- [ ] 用户可提交工单（关联订单号）
- [ ] 客服可接单 / 处理 / 关闭；非法状态流转被拒绝
- [ ] 状态：待处理 → 处理中 → 已关闭
- [ ] 用户只能看自己的工单；admin 能看全部
- [ ] 列表使用若依分页、权限字、字典（工单类型）
- [ ] 前端符合若依规范：查询栏 + 表格 + 弹窗 + 按钮权限
- [ ] 已部署：MySQL + Redis + 后端 jar + 前端 `npm build` + Nginx
- [ ] 能用两个角色演示 3 分钟

## 硬性约束

- 表结构自己设计；**禁止**用代码生成器作为该模块最终代码（可先生成对照，提交的必须是手写）
- 必须有：权限字、`sys_menu` 插入 SQL、字典
- 必须有：和订单的关联（可只用订单号字段，不必改若依原订单表）

---

## 工作日建议（每天 3h）

### 周一

- 设计 `biz_ticket`（或同类名）表：单号、用户、订单号、类型、状态、处理人、内容、时间
- 写 `sys_menu` 权限 SQL（目录 / 菜单 / 按钮：查询、新增、接单、关闭）
- 建实体、Mapper，先跑通空列表接口

### 周二

- 提交、列表、详情
- 数据权限：普通用户按 `user_id` 过滤；admin 不过滤
- 字典：工单类型（质量问题 / 物流 / 其他）

### 周三

- 接单、关闭的状态流转
- 待处理才能接单；处理中才能关闭；已关闭不能再改
- 只有具备对应权限字的角色能接单

### 周四

- 若依前端：`api` + `vue` 页面
- 查询栏、表格、新增弹窗、操作按钮
- 按钮绑定权限字，和后端 403 对上

### 周五

- 联调、修 bug
- 接上操作日志（若依自带 `@Log` 即可）
- 写 README：模块说明、菜单 SQL、演示账号、架构对照第 4 周

### 周六（3～4h）

- 部署一遍：MySQL + Redis + jar + 前端 dist + Nginx
- 录演示：admin 接单 vs 普通用户只看自己的单
- 打 tag：`work2-v1`

### 周日（2～3h）

- 6 周总复盘口述（见下方清单）
- 简历子弹：作品 1 自研商城、作品 2 若依工单，各写 3 条「做了什么 + 难点 + 结果」

4. 角色、菜单、权限字、数据权限各管什么？
5. 若依和你自己写的后台，权限实现差在哪里？
6. 慢 SQL 你准备怎么查（`EXPLAIN`、索引）？

- 二次开发和「只会点代码生成器」的差别
